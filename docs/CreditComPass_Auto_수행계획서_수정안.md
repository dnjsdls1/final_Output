# CreditComPass Auto 프로젝트 수행계획서 수정안

## 수정 방향 요약

기존 수행계획서는 **신용평가모형 개발과 신용관리 서비스**를 중심으로 작성되어 있다. 현재 구현된 서비스는 **재무·신용정보와 차량 이용조건을 활용한 차량 구매 가능 예산 분석 및 맞춤 차량 추천 프론트엔드 프로토타입**이다.

따라서 프로젝트 주제, 성과목표, 주요 기능, 적용 기술, 일정 및 기대효과를 현재 구현 범위에 맞게 수정하는 것이 좋다. 실제 신용평가, 대출 심사 또는 금융상품 추천으로 오해되지 않도록 모든 분석 결과가 mock 데이터와 예시 계산 규칙을 사용한다는 점도 명시해야 한다.

## 1. 프로젝트 기본정보

### 프로젝트명

**CreditComPass Auto**

### 주제

재무·신용정보와 차량 이용조건을 활용한 차량 구매 가능 예산 분석 및 맞춤 차량 추천 서비스

### 기술 분야

- SW 웹 애플리케이션
- 금융 데이터 분석 및 차량 추천 프론트엔드 프로토타입

## 2. 성과목표

- 사용자의 소득, 지출, 보유자산, 대출 및 신용거래 정보를 입력받아 차량 구매에 활용할 수 있는 월 여유자금을 계산한다.
- 원하는 선수금과 할부기간을 바탕으로 월 납입 가능액과 적정 차량가격 범위를 예시로 제시한다.
- 차량 구매 목적, 주행거리, 선호 차종 및 연료 등의 조건을 반영하여 차량 추천 목록을 제공한다.
- 분석 결과와 추천 이유를 카드와 차트로 시각화하여 사용자가 차량 구매 판단 과정을 쉽게 이해하도록 한다.
- 입력, 분석 결과, 추천 차량 확인으로 이어지는 핵심 사용자 흐름을 프론트엔드 프로토타입으로 검증한다.

---

## 3. 프로젝트 소개 및 제안 배경

첫 차량을 구매하려는 사용자는 차량 가격뿐 아니라 선수금, 할부기간, 기존 대출 상환액, 생활비 등을 함께 고려해야 한다. 그러나 일반적인 차량 검색 서비스는 차량의 가격이나 제원 비교에 집중되어 있어 사용자가 자신의 재무 상황에서 실제로 감당할 수 있는 차량 범위를 판단하기 어렵다.

본 프로젝트는 사용자의 월 실수령액, 고정지출, 생활비, 보유자산, 기존 대출 및 신용거래 정보와 차량 이용조건을 입력받아 월 납입 가능액과 적정 차량가격 범위를 분석하는 웹서비스를 구현한다. 분석 결과를 차트와 쉬운 설명으로 제공하고, 사용자 조건에 맞는 차량과 추천 이유를 함께 제시하여 합리적인 차량 구매 판단을 지원한다.

현재 단계에서는 핵심 서비스 흐름을 검증하기 위해 mock 데이터와 예시 계산 규칙을 사용한 프론트엔드 프로토타입으로 구현한다. 표시되는 금액과 추천 결과는 실제 금융심사 또는 대출 가능 여부를 의미하지 않는다.

| S/W | 차량 이용조건 입력 | 구매 목적, 주행거리, 주요 도로, 탑승 인원, 선호 차종·연료, 선수금 및 할부기간을 입력받는다. |
| S/W | 종합 재무 분석 | 월 납입 가능액, 재무 안정성, 추천 차량가격 범위와 소득 사용처를 카드 및 차트로 보여준다. |

| S/W | 조건별 차량 비교 | 경차, 세단, SUV, 가솔린, 하이브리드 등의 조건으로 추천 결과를 필터링한다. |
| S/W | 입력값 수정 및 재분석 | 사용자가 입력 화면으로 돌아가 조건을 변경하고 새로운 결과를 확인할 수 있도록 한다. |

### 화면 구성

- `/main`: 서비스 소개
- `/apply`: 재무·신용정보 및 차량정보 입력
- `/result`: 종합 분석 결과
- `/recommendations`: 추천 차량 목록

## 5. 적용 기술

### 프론트엔드

- Vite와 React를 활용하여 화면과 사용자 입력 흐름을 구현한다.
- React Router를 이용하여 메인, 입력, 분석 결과, 추천 차량 화면을 연결한다.
- styled-components를 이용하여 화면별 디자인과 공통 레이아웃을 구성한다.
- Recharts를 이용하여 월 소득 사용처와 현재·권장 수준을 시각화한다.

### 상태 및 데이터 관리

- Zustand와 persist 기능을 이용하여 사용자의 입력값을 저장한다.
- Mock JSON과 비동기 API 함수를 이용하여 분석 결과와 추천 차량 데이터를 제공한다.
- 실제 API로 교체할 수 있도록 화면이 mock 파일을 직접 사용하지 않고 데이터 접근 함수를 호출하도록 구성한다.

### 협업 및 설계

- Figma: 사용자 화면과 이용 흐름 설계
- Git·GitHub·Sourcetree: 소스 변경 이력 및 협업 관리
- Notion: 일정, 회의록 및 업무 진행 상황 관리

### 향후 확장 기술

향후 확장 단계에서 Spring Boot API, 데이터베이스 및 실제 추천모형과 연동할 수 있다. 현재 수행 범위는 프론트엔드 프로토타입과 mock 데이터 기반 사용자 흐름 검증이다.

현재 기능에는 별도의 검색 요구사항이 없으므로 Elasticsearch는 적용 기술에서 제외하는 것이 좋다.

## 6. 예상 결과물

### 화면 결과물

1. **메인 화면**  
   서비스 목적, 진행 단계, 예상 차량 예산과 추천 차량 미리보기를 보여준다.

2. **단계형 입력 화면**  
   재무·신용정보와 차량 이용조건을 입력받고 Zustand에 저장한다.

   월 납입 가능액, 재무 안정성, 권장 차량가격과 분석 차트를 제공한다.

4. **차량 추천 화면**  
   차량 6대의 가격, 연료, 연비, 예상 월 납입액과 추천 이유를 비교한다.

- React 프론트엔드 소스 코드
- Mock 데이터 및 비동기 데이터 접근 함수
- API 요청·응답 초안
- 모델 입력·출력 정의서
- 확인이 필요한 금융·차량 정보 목록
- 발표 및 시연 자료

## 8. 의사소통 방법 및 Ground Rule 보완안

- 화면 구현 전 입력항목, 출력항목, 추천 근거와 사용자의 다음 행동을 팀원 간 합의한다.
- 화면은 한 번에 하나씩 구현하고 완료 후 브라우저에서 기능과 디자인을 검증한다.
- Mock API가 추가되거나 변경되면 API 초안 문서를 함께 수정한다.
- 화면 또는 모델 입력·출력이 변경되면 모델 카드 문서를 함께 수정한다.
- 금융 관련 수치와 차량 정보는 출처를 확인하고, 검증 전 수치는 예시값으로 표시한다.
- 코드 병합 전 입력 검증, 상태 저장, 화면 이동 및 오류 상태를 확인한다.
- 기존 수행계획서의 의사소통 부분에 단독으로 입력된 `s` 문자는 삭제한다.

## 9. 기대효과

- 사용자가 차량 가격만 보는 대신 소득, 생활비, 기존 대출과 월 상환액을 함께 고려하여 구매 가능 범위를 확인할 수 있다.
- 월 납입 가능액과 추천 차량가격 범위를 시각화하여 복잡한 재무정보를 쉽게 이해할 수 있다.
- 차량별 추천 이유와 예상 부담을 함께 제시하여 추천 결과를 사용자가 비교하고 납득할 수 있다.
- 재무 조건과 차량 이용조건을 한 서비스에서 함께 분석하여 일반 차량 검색 서비스와 차별화할 수 있다.
- 실제 모델과 API를 개발하기 전에 입력·분석·추천으로 이어지는 핵심 사용자 흐름을 검증할 수 있다.

## 최종 점검사항

- 프로젝트명과 서비스명이 `CreditComPass Auto`로 통일되어 있는지 확인한다.
- 신용평가 서비스로 남아 있는 설명을 차량 구매 여력 분석 서비스에 맞게 수정한다.
- 현재 구현하지 않은 백엔드, DB, 검색엔진과 실제 ML 모델을 완료 기능처럼 표현하지 않는다.
- 금액, 추천 적합도, 차량 가격과 연비가 예시값임을 문서와 화면에 명시한다.
- 예상 결과물 표에는 `/main`, `/apply`, `/result`, `/recommendations` 화면 이미지를 순서대로 배치한다.
- 실제 금융심사, 대출 자격 또는 신용평가 결과로 오해되지 않도록 면책 문구를 포함한다.
